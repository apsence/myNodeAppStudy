# Архитектура и принятые решения

## Слои
```
routes → middleware (validation, auth, upload) → controllers (HTTP) → services (бизнес-логика) → models (MongoDB)
```
* **models** — единственное место с синтаксисом MongoDB; чтобы сменить СУБД, переписывают только их.
* **services** — зависимости (модель, почта, хэширование, шина событий, хранилище файлов) передаются в конструктор,
  поэтому сервисы тестируются изолированно, без БД.
* **controllers** — только HTTP: берут проверенные данные из `ctx.state.validated`, выставляют статус и тело.
* **app.js** — фабрика `createApp(deps)`: в интеграционных тестах подставляются поддельные сервисы.

## Безопасность
| Угроза | Мера |
|---|---|
| Подбор паролей | bcrypt (10 раундов), одинаковый ответ «Invalid credentials», выравнивание времени для несуществующего email, rate limit, лог всех попыток |
| Кража/подмена токена | HS256 зафиксирован в `verify`, разные секреты access/refresh, секреты только из env (проверка длины при старте), refresh с jti и ротацией, отзыв при logout и удалении пользователя |
| NoSQL-инъекции | Joi-типизация (`string`), санитайзер ключей `$…`/`.`, в модель попадают только проверенные значения |
| XSS/кликджекинг и др. | Helmet |
| Чужие источники | CORS по белому списку |
| Перегрузка | rate limit 100 запросов/мин на IP, лимит размера тела (1 МБ), лимит файла (2 МБ) |
| Загрузка файлов | белый список MIME, проверка сигнатуры файла, имена генерирует сервер, защита от path traversal при раздаче |
| CSV-инъекции | экранирование ячеек, префикс `'` для `= + - @` |
| Утечки | хэш пароля никогда не читается из БД обычными запросами, 500-ответы без деталей, секреты маскируются в логах |

## Мягкое удаление
`DELETE` ставит `deleted_at`; обычные запросы фильтруют `deleted_at: { $exists: false }`.
Уникальность email сохраняется и для удалённых (MongoDB не поддерживает `$exists: false` в partial-индексах), поэтому повторная
регистрация на удалённый email даёт 409, пока администратор не восстановит запись.

## Наблюдаемость
JSON-логи (pino) с `requestId`; метрики Prometheus (метка `path` — шаблон маршрута); `/health` (liveness), `/ready` (БД).
